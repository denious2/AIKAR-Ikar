# 🚀 N-Sonic Ikar Engine — AI Developer Guide
Это руководство описывает архитектуру и правила работы с генератором лирик-видео Ikar. 
**Если ты ИИ-агент, ВНИМАТЕЛЬНО изучи этот файл перед внесением любых изменений в код или конфигурации.**

## 📂 1. Архитектура проекта
Проект строго разделен на ядро генерации (`core/`), конфигурации (`configs/`) и медиа-ассеты (`media/`).

*   **`configs/config.json`** — Базовые настройки рендера, тестового режима и структура трека.
*   **`configs/director-config.json`** — Режиссерский пульт (пулы ассетов, акценты, Overrides, правила секций).
*   **`configs/library-config.json`** — Библиотека CSS-анимаций, LUT'ов, эффектов (никогда не хардкодить CSS в JS!).
*   **`package.json`** — Точка входа. Команда `npm run start` запускает `node core/run.js`.
*   **`core/run.js`** — Главный оркестратор. Запускает билдеры строго по очереди.
*   **`core/config_loader.js`** — ЕДИНЫЙ загрузчик конфигураций и логгер. Все JS скрипты обязаны использовать его.
*   **`core/build/`** — Скрипты-сборщики HTML-сцен (аудио, биты, пыль, субтитры, параллакс, индекс).
*   **`core/utils/`** — Утилиты анализа аудио (экстрактор баса, битов, акцентов).
*   **`core/utils/images/`** — Изолированные утилиты для сборки параллакса (магнит, сканер, генератор HTML).
*   **`media/`** — Исходные медиафайлы (mp3, картинки, видео, субтитры).
*   **`compositions/`** — Сгенерированные HTML/CSS файлы перед рендером в Hyperframes.

## ⚠️ 2. Строгие правила для ИИ-разработчика (НЕ НАРУШАТЬ)
1.  **НИКАКОГО ХАРДКОДА ПУТЕЙ И ИМЕН ФАЙЛОВ.** Все пути строятся динамически от корня проекта (`process.cwd()`).
2.  **ИМПОРТ ИЗ `config_loader.js`.** При создании или правке скриптов в `core/build/` или `core/utils/`, конфигурации должны загружаться через `import { loadConfigs } from '../config_loader.js'` (или с учетом правильного уровня вложенности). Не читай JSON напрямую через `fs.readFileSync`.
3.  **РАСШИРЕНИЯ ФАЙЛОВ В ES-МОДУЛЯХ.** При импорте локальных модулей **ОБЯЗАТЕЛЬНО** указывай `.js` в конце пути (например, `import { x } from './utils.js'`).
4.  **АНИМАЦИИ ТОЛЬКО ЧЕРЕЗ БИБЛИОТЕКУ.** Не добавляй новые `@keyframes` напрямую в HTML-генераторы. Все новые эффекты должны добавляться в `library-config.json`, а скрипты должны подтягивать их оттуда.

## 🥞 3. Z-Index и Треки (Слои композиции)
Движок рендерит слои в строгом порядке наложения.
*   **Слой -1:** Аудио трек (невидим)
*   **Слой 1:** Задние атмосферные видеоэффекты (`host-visuals-bg`)
*   **Слой 2:** Главный нарратив / Картинки (`host-images`)
*   **Слой 3:** Передние эффекты / Переходы (`host-visuals-fg`)
*   **Слой 4:** Пыль, текстура бумаги, шум (`host-dust`)
*   **Слой 45:** Ритмические строб-вспышки (`host-beats`)
*   **Слой [9950]:** Shadow Crush (Мягкое затемнение под бас, `shadow-crush-overlay`)
*   **Слой 5 [10000]:** Субтитры (`host-subs`). Оснащены кинетическим якорем.
*   **Слой 6 [9998]:** Глобальная Цветокоррекция / LUT (`host-color-grade`)
*   **Слой 46 [9999]:** Глобальные видео-акценты / Глитчи (`host-accents`)

## 🧲 4. Ритмический Магнит (Rhythm Magnet)
В `core/utils/images/rhythm_magnet.js` заложена логика автоматической подгонки картинок под аудио.
1. Ищет ближайший маркер субтитра в окне `[MIN_IMG_DURATION ... MAX_IMG_DURATION]`.
2. Если субтитра нет, ищет ближайший удар барабана (бит).
3. Если это видеофайл и он короче расчетного времени — обрезает кадр по реальной длине видео.
4. "Сшиватель границ": если до конца музыкальной секции остался "огрызок" меньше `MIN_IMG_DURATION`, растягивает текущий кадр до конца секции.
5. `directorOverrides` всегда имеют наивысший приоритет над магнитом.

## 📌 5. Как тестировать изменения
*   Команда `npm run start` запускает полный цикл: анализ аудио -> генерация сцен -> рендер.
*   Для быстрой визуальной отладки эффектов на одной картинке используй `node core/utils/test_stend.js` (результат смотреть в `compositions/test_stend.html`).
